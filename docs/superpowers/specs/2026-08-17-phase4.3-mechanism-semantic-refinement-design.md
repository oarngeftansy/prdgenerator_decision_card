# Phase 4.3 Mechanism Semantic Refinement

## Scope

Refine the six Phase 4.2 samples without creating Rule, closing Gap, or entering EntityBuilder, ParameterResolver, P5, or P6.

## Public interfaces

- `compose_mechanism_blocks(chapter, approved_rules, reviewed_gaps, schema)`
- `render_mechanism_block(block, style_profile)`

## Role resolution

Resolution order is fixed: structured Rule fields; ChapterType + SchemaSlot + RuleType; deterministic predicate pattern only for ambiguity; neutral descriptive handling when still unresolved. Every assignment records `roleAssignmentReason`.

Roles are `definition`, `input_constraint`, `trigger`, `condition`, `target_selection`, `processing`, `effect`, `state_change`, `result`, `exit_boundary`, `presentation`, and `config_reference`.

## Resolution status

Each Rule assignment is `executable`, `descriptive`, or `unresolved_dependency`. Unresolved dependencies remain traceable in JSON and appear only in the open-decision summary.

## Composition and rendering

Blocks merge only by chapter ID, owner, mechanism semantic, and compatible role domain. Same-title blocks with different owners or domains remain separate and produce a conflict record. Final prose chooses sentence, bullets, numbered steps, or table from confirmed structure. Internal carrier labels never appear in final Markdown.

## Acceptance

Produce six Rule → Role → Block → Final outputs, a Phase 4.2 → 4.3 role audit, correction/merge/conflict/unresolved metrics, zero final-Markdown internal labels, zero unsupported semantic additions, and 100% traceability for Rules eligible for confirmed prose or open-decision summaries.
