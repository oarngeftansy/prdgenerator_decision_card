# 玩法章节结论卡片式审核设计

## 目标

把玩法章节审核从字段表单改为策划可以快速判断的结论卡片。策划首先判断 AI 对玩法的理解是否正确，只在需要修改或确实存在补充内容时处理细节。

## 默认阅读顺序

每个章节默认只展示以下内容：

1. 章节名称。
2. 不超过四句话的玩法结论，依次说明玩家怎么玩、何时发生、产生什么变化以及最终结果。
3. 最多三张保持原始比例的参考画面。
4. 三个互斥判断：`识别正确`、`部分正确，需要修改`、`这一章不适用`。

默认界面不展示空白数值、内部字段、关联标识或程序状态。

## 策划判断

### 识别正确

保存当前玩法结论和对应素材依据。界面显示明确的保存状态；成功后自动进入下一未确认章节。

### 部分正确，需要修改

在当前卡片中展开玩法说明编辑区。策划直接修改面向最终策划案的玩法说明，不需要理解底层结构。修改内容保存后仍需选择审核结论。

### 这一章不适用

把该章节标记为不适用于当前素材，不再要求填写数值或其他补充项；保存后进入下一未确认章节。

三个判断互斥，切换判断不得丢失已经输入但尚未提交的修改内容。

## 补充细节

数值、影响其他内容、检查方法和待确认事项统一收进“补充细节”。只有满足以下任一条件时才显示入口：

- 当前章节确实识别出有效内容；
- 存在阻止本章通过的问题；
- 策划选择“部分正确，需要修改”；
- 策划主动展开。

补充细节内部使用策划语言：

- “游戏中的数值和条件”代替参数、字段、类型等内部表达；
- “还会影响哪些玩法”代替关联章节或依赖；
- “怎么检查这项玩法是否正确”代替验收条件；
- “还需要策划判断的内容”代替未知项或阻断项。

不存在内容的分组不渲染，不用空输入框占位。展开状态由用户控制，保存或点击空白处不得自动收起。

## 数据与兼容性

继续使用现有章节、玩法结论、素材依据、数值、关联内容、检查方法和待确认事项数据，不修改后端保存格式。前端只改变信息分层和提交入口，保证已有任务能够继续审核，最终飞书文档仍读取已确认的结构化内容。

选择结果映射到现有审核结论：

- `识别正确`映射为通过；
- `部分正确，需要修改`保留为待修改，完成修改后可再次通过；
- `这一章不适用`映射为不适用处理，不进入最终玩法正文。

## 保存与异常反馈

提交后在判断按钮附近显示“正在保存”。成功时显示具体结果并自动进入下一未确认章节；失败时留在当前章节，保留选择、编辑内容和展开状态，并显示策划可理解的失败原因。重复点击提交按钮不得产生并发保存。

## 测试边界

测试只覆盖用户可观察的公开交互：

1. 章节审核界面默认只展示玩法结论、参考画面和三个互斥判断。
2. 选择“部分正确，需要修改”后出现玩法说明编辑区。
3. 没有有效内容的补充细节分组不显示。
4. 有效补充内容能够由用户手动展开，并且不会因保存或点击空白处自动收起。
5. 三个判断保持互斥，切换时不清空未提交修改。
6. 提交时显示保存状态，失败保留当前内容，成功进入下一未确认章节。
7. 旧任务数据无需迁移即可继续审核并输出最终文档。

## 不在本次范围

- 不改变玩法目录的自动拆分逻辑。
- 不修改视觉模型识别流程。
- 不改变最终飞书文档的章节结构。
- 不实现当前版本已关闭的红色编号 UE 流转图。
