# UE 流转图独立审核阶段设计

## 目标

在原 P1–P7 审核台中新增一个独立的 UE 流转图审核阶段。该阶段位于“交互流程审核”之后、“交互交付物预览”之前，用于检查由已确认交互数据生成的完整页面流转图。

本阶段不创建第二套交互事实，不允许直接编辑页面、节点、跳转或证据。所有修改返回上一阶段完成。

## 工作流位置

原流程中的后续阶段顺延：

`P2 交互流程审核 → P3 UE 流转图审核 → P4 交互交付物预览 → 后续玩法审核阶段`

顶栏阶段、页面标题、URL、刷新恢复、页面内继续操作及持久化状态必须使用同一阶段定义，禁止只修改可见编号。

## 权威数据源

UE 流转图只消费当前交互审核模型中已经确认的数据：

- `stages`
- `transitions`
- `representativeFrames`
- Transition 的来源页面、目标页面、触发类型、触发说明、条件、系统反馈与结果状态
- 页面内部已确认的连续状态或子流程

不得从截图标题、相邻顺序、AI 常识或旧图文本重新猜测跳转。P2 交互审核模型是唯一 source of truth。

## 页面布局

页面沿用原审核台外壳、字体、颜色、间距、导航和操作区，不新增独立站点或视觉域。

### 左栏：流程目录

- 按交互环节列出页面节点。
- 展示主流程、分支、循环、返回和结束节点的层级关系。
- 显示节点状态：正常、存在问题、当前选中。
- 点击目录项只定位图中节点并更新右侧详情。

### 中栏：UE 流转图

- 使用真实代表帧展示页面节点。
- 使用已确认 Transition 连接页面。
- 连线显示玩家操作或系统触发的自然语言摘要。
- 支持缩放、平移、适应画布与回到当前节点。
- 节点和连线可选中，但不可拖动、改线或新增内容。
- 同一页面内部连续状态作为页面子流程表达，不机械拆成多个页面。
- 分支、返回、循环和结束使用不同但与原审核台一致的视觉标识。

### 右栏：审核依据

选中页面节点时展示：

- 页面名称与用途
- 代表帧及来源
- 进入页面的条件
- 从页面离开的已确认操作

选中连线时展示：

- 来源页面与目标页面
- 玩家操作或系统触发
- 成立条件
- 系统反馈
- 操作结果
- 对应证据与 P2 Transition

右栏只展示可读摘要。内部 ID 和完整证据调试信息默认折叠。

### 页面底部动作

- `返回 P2 修改`：定位到当前问题关联的 Stage 或 Transition。
- `重新生成`：重新消费当前 P2 已确认数据，不调用 AI 补造关系。
- `确认 UE 流转图并进入交互交付物预览`：仅在所有阻塞项消除后可用。

## 审核与阻塞规则

以下情况阻止确认：

- 页面缺少可用代表帧。
- Transition 来源或目标页面不存在。
- 主流程存在无法解释的悬空节点。
- Transition 仍为 unknown 或未确认。
- 图的来源 revision 落后于当前 P2 interaction revision。
- 网页预览与飞书画板使用的图数据或生成指纹不一致。

非阻塞提示可以包括图过密、交叉线较多或同页子流程可读性不足，但不得自动修改权威数据。

## 版本与状态

- 生成图时记录 `sourceInteractionRevision` 与图指纹。
- 主策确认后记录对应的 `ueFlowReviewRevision`。
- P2 任一 Stage、Transition 或代表帧发生变化后，已确认 UE 图立即标记为过期。
- 过期图可查看，但禁止推进到交互交付物预览。
- 刷新页面后恢复当前选中节点、缩放位置和审核状态；这些 UI 状态不能改变业务数据。

## 职责边界

### UE 流转图

回答“页面和状态如何流转”，承载页面节点、触发、分支、返回、循环和结束关系。

### 交互交付物预览 / 策划草图

回答“单个页面如何交互和表现”，承载页面用途、区域、控件、反馈、动效、提示和表现要求。

两者使用同一交互模型，但不得重复定义对方职责。UE 图中的红色步骤编号只用于流转识别，不进入策划草图默认视图。

## 线框稿范围

首个 `线框图.html` 仅用于确认页面结构与审核路径：

- 复用原审核台视觉外壳。
- 展示新增 P3 在完整阶段导航中的位置。
- 使用示例页面节点、分支和详情，不接真实任务接口。
- 可点击节点、连线、目录、缩放控件和底部动作。
- `返回 P2 修改`与`确认并进入 P4`只做线框态反馈，不修改任务。
- 不修改后端、真实路由、`job.json` 或正式 P1–P7 工作流。

## 验收缝隙

正式实现阶段的行为验收位于以下公共接口：

1. 原审核台阶段导航：新增 P3 后，URL、可见页面、刷新恢复和持久化一致。
2. UE 图审核页面：只读选择、缩放、目录定位和依据详情工作正常。
3. P2 数据变更：旧图变为过期，不能继续。
4. 阻塞定位：可返回 P2 对应 Stage/Transition。
5. 确认推进：只在当前 revision 无阻塞时进入 P4。
6. 同源交付：网页 UE 图与飞书 UE 画板读取同一结构化图和指纹。

## 非目标

- 不在 UE 图中直接编辑交互事实。
- 不新增 AI 推断关系。
- 不重做 P2 交互审核。
- 不修改策划草图的内容模型。
- 不把 Mechanic Review、Final Publication 或独立预览页面并入本阶段。

## 最终交付入口

- 最终结果必须进入原“言灵镜瞳”P1–P7 工作台，不创建新的正式域名、独立审核台或平行发布页。
- 新增 UE 流转图阶段后，后续阶段顺延；最终文档预览仍是工作台内唯一正式 Publication 入口。
- Mechanic Review 仍是内部审核能力。经 Accept/Edit 产生的 Approved Rule 必须通过 Requirement Closure、RuleChain、Chapter Assembly 后进入原最终文档预览。
- 最终文档正文只消费 Confirmed Rule、Approved Rule 和已批准参数；Requirement、Proposal、Placeholder、AI 推演标签与审核状态不得发布。
- 表现与交互内容进入策划草图；UE 页面/状态流转进入 UE 流转图；核心玩法逻辑进入执行策划正文。

## 最终文档顺序

同一发布快照按以下顺序组装：

1. 变更记录
2. 文档概述
3. UE 流转图
4. 交互交付物预览 / 策划草图
5. 竞品参考（当前项目存在且已确认时）
6. 正式执行策划案各自然系统章节

章节编号由最终实际内容动态计算，不因示例顺序固定游戏章节 Schema。

## 变更记录

文档开头使用表格记录本次发布：

| 版本 | 日期 | 变更范围 | 变更说明 | 审核状态 |
|---|---|---|---|---|
| 当前发布版本 | 发布日期 | 全量重构 | 说明 UE 流转图、交互交付物、Approved Mechanic Rule 与最终章节已按当前审核结果重组 | 已确认 |

变更记录只描述真实发布变更，不写内部 Proposal、Requirement、Phase 或审计 ID。
