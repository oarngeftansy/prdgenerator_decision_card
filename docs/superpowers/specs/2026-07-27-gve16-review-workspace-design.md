# GVE16 交互策划审核工作台设计规格

日期：2026-07-27
状态：设计已确认，等待书面规格复核

## 1. 目标

将截图优先分析得到的 AI 草稿，经过可恢复、可定位、分层确认的人工审核，稳定转换为符合 GVE16 颗粒度的移动端交互策划案，并继续输出为对齐成功样例的飞书正文和原生 UE 流转画板。

FlowDoc 只提供审核方式：流程筛选、局部框选、跳转定位、联动编辑和确认步骤。GVE16 决定最终交付内容。FlowDoc 的视图、字段名和 Figma 工程逻辑不得成为飞书正文的新章节。

## 2. 标准优先级

1. GVE16 与 `gve16-planning-schema`：决定“大流程 → 环节 → 小循环 → 区域/组件 → 条件 → 操作/自动触发 → 反馈 → 结果/异常”的策划颗粒度。
2. 成功文档 `TVnddRv6FoGFE0xTSMkcKNSunpc`：决定正文标题、章节顺序和内容槽位。
3. 成功文档 `ZNWkd0Ke3oZCtAxDQA5ckxonnJS`：决定 UE 画板 Section、代表截图、红色编号、说明和往返连线的表达。
4. FlowDoc：决定用户如何筛选 AI 候选、定位触发点、调整组件框和确认数据。

## 3. 范围

### 一期

- 上传完成后进入全宽、分阶段审核工作台。
- 全流程视图：候选转换筛选、转换详情、横向环节泳道和流程确认。
- 环节视图：多张代表状态图、可拖拽组件框、红色编号、区域规则和逐环节确认。
- 导出预览：GVE16 正文目录、UE 图预览、阻断项、待确认项和显式飞书导出。
- 共享审核模型、自动保存、撤销/重做、历史恢复、AI 建议保护和确认失效规则。

### 二期

- 独立组件视图。
- 组件状态的批量编辑和跨页面组件复用。
- 更完整的键盘精调、对齐辅助、复杂组件关系和大规模组件管理。

一期已包含完成 GVE16 标注所必需的组件框创建、移动、缩放、编号和规则绑定；二期不作为一期导出 GVE16 的前置条件。

### 非目标

- 不复刻 FlowDoc 的视觉风格和全部 Figma 功能。
- 不把网站变成通用自由画板。
- 不要求每个环节固定一张截图或固定存在点击跳转。
- 不把所有上传截图写入飞书正文或 UE 画板。
- 策划上传并确认的截图顺序，默认代表环节先后与流程关系；具体触发方式仍由画面分析或人工审核确定，不能把所有相邻关系一律写成点击。

## 4. 页面与审核状态

上传页和审核工作台为两个明确工作状态。上传完成后进入全宽工作台，素材、基础信息和历史任务收进可展开项目资料抽屉，不继续挤压审核画布。

一期顶部步骤为：

`AI 草稿 → 全流程审核 → 流程确认 → 环节审核 → 环节全部确认 → 导出预览 → 飞书导出`

状态规则：

- 修改环节顺序、增删环节或关键跨环节转换，会解除流程确认、全部环节确认和旧导出预览。
- 修改单个环节的代表截图、区域、组件框或规则，只解除该环节确认和旧导出预览。
- 修改非结构性备注时只更新预览版本，不解除无关环节确认。
- 未保存修改不得标记为已确认。
- 刷新或重开历史任务时恢复当前步骤、选中环节、选中对象、审核进度和未解决项。

## 5. 单一 GVE16 审核模型

所有视图读写同一份模型。视图状态单独保存，不复制策划数据。

### 5.1 环节 `stages`

每个环节至少保存：

- 稳定 ID、名称、顺序和类型。
- 用户目标、进入条件和退出条件。
- 父页面、所属 Section 和是否为流程终点。
- `representativeFrames`：一至三张代表状态图及其角色。
- 环节内部小循环和关联转换。
- 确认状态、人工修改版本和待确认项。

代表图角色包括：`entry/default`、`interaction/change`、`result/exit`。全流程泳道只显示一张封面；环节视图和飞书 UE 图按实际解释需要使用一至三张，不机械执行“一环节一张”。

### 5.2 转换 `transitions`

每条转换至少保存：

- 稳定 ID、来源环节和可为空的目标环节。
- 触发类型、触发条件和触发对象。
- 可选组件 ID、可选点击锚点和来源截图 ID。
- 系统响应、结果类型、结果状态。
- 条件成立分支和不成立分支。
- 主流程标记、来源类型、置信度和确认状态。

触发类型至少包括：点击、长按、滑动/拖拽、动画结束、媒体播放结束、等待时间、条件满足、系统事件和未知待确认。

结果类型至少包括：进入其他环节/页面、当前环节状态变化、打开/关闭弹窗、返回、循环、流程结束和未知待确认。

自动转换没有点击锚点。流程终点允许目标为空。当前页内部状态变化不得被强制拆成新页面。

### 5.3 区域与组件 `regions/components`

每个可编辑框至少保存：

- 稳定 ID、所属环节、页面、截图和父区域。
- 类型、名称、显示标签和功能说明。
- 归一化 `x/y/width/height`。
- 显示内容、进入条件、用户操作或自动触发。
- 系统反馈、结果状态、目标页面和异常。
- 主交互标记、来源类型、确认状态和人工修改历史。

内部稳定 ID 与显示编号分离。显示编号可以重排，绑定关系不能依赖编号或坐标猜测。

### 5.4 组件状态 `componentStates`

状态槽至少包括：默认、按下、选中、禁用、加载、成功、错误、次数耗尽和条件不满足。素材未展示的状态保留“待确认”，不得自动补全为事实。

### 5.5 跨状态约束 `crossStateConstraints`

独立保存不属于单一组件的规则，例如：选择结果是否继承、返回是否恢复状态、资源和次数是否保留、弹窗是否暂停背景、重复进入是否初始化、动画期间能否操作、失败后如何恢复。它们在全流程审核，并映射为 UE 画板黄色说明。

### 5.6 审核与修改 `reviewState/editHistory`

- 流程确认、逐环节确认、当前修订版本和预览版本。
- 最近选中的视图、环节、转换、截图和区域。
- 最多 50 步撤销/重做操作。
- 人工字段、AI 建议字段和建议采纳记录。
- 核心阻断项和非核心待确认项。

## 6. 全流程视图

### 6.1 候选转换筛选

生成泳道前先按来源页面/环节分组展示 AI 候选转换。每组显示数量，每条显示触发类型、组件或系统事件、目标环节、来源级别和置信度。

用户可以单条勾选、全选、全不选、新增、删除和执行语义去重。默认优先保留 `primary=true` 的主交互；低置信度、重复关系和仅有视觉变化的候选等待用户处理。未被保留的候选不进入最终流程。

### 6.2 转换详情审核

保留后的转换逐条审核，支持上一条、下一条和新增转换。

- 点击型：显示来源截图、绑定组件框和点击锚点。锚点可在组件框内拖动并保存归一化坐标。
- 未识别到点击组件：用户先创建或选择组件框，再绑定锚点。
- 同一组件多条转换：每条转换拥有独立锚点和结果。
- 自动型：不显示虚假点击位置，改为编辑动画结束、媒体结束、等待时间或系统条件。
- 状态变化：留在当前环节内部。
- 终点：允许没有目标环节。
- 触发方式无法证明：保存为未知待确认。

### 6.3 横向环节泳道

主流程固定从左到右，卡片展示封面代表图、环节名、入口、出口、转换数量和待确认数量。卡片支持拖拽排序和等价的上移/下移按钮。异常和条件分支挂在对应环节下方并默认折叠。

点击卡片进入环节视图；点击连线进入转换详情。全流程确认前检查环节名称、顺序、入口、出口、关键目标和主流程闭环。

## 7. 环节视图

桌面端采用“截图与当前区域规则并排”；移动端采用“画面 / 规则”页签。一次只编辑当前选中的区域或组件，避免长表单。

### 7.1 代表状态图

默认显示环节的一至三张代表状态图，并保留“查看全部截图”。展开全部截图不改变代表图选择。用户可以为代表图指定进入、变化或结果角色。

### 7.2 框选、编号与选择同步

- AI 提供初始区域/组件框和编号。
- 用户可拖拽空白位置创建新框。
- 拖动框主体移动；拖动边和角点调整宽高。
- 框不得超出图片边界，并设置最小尺寸。
- 截图框、红色编号、区域标签、组件列表和右侧规则共享同一选中对象。
- 用户可调整编号顺序和编号位置；内部稳定 ID 不变。
- 框选、移动、缩放、增删和重排进入撤销/重做记录，并在操作结束时保存。
- 删除已绑定转换的组件时，必须先处理关联关系。

每个标注绑定同一条 GVE16 规则：显示内容、条件、操作或自动触发、反馈、结果、异常和待确认项。导出时按最终环节顺序生成全局连续红色编号，并与旁侧规则一一对应。

### 7.3 环节小循环

每个环节必须形成：

`进入条件 → 界面展示 → 操作/自动触发 → 系统反馈 → 状态变化 → 退出、返回或重试`

缺少核心节点时不能确认环节。刷新、次数耗尽、条件不足、重复操作和未完成操作等分支应在素材明确展示或用户确认后进入规则；否则保留待确认。

## 8. 导出预览

导出预览只读展示：

- 最终 GVE16 正文目录和章节完整性。
- UE 流转图缩略预览。
- 环节、代表图、红色编号和黄色说明数量。
- 核心阻断项、非核心待确认项和验收错误。
- 当前模型修订版本与预览版本是否一致。

用户可以从错误项直接返回对应流程、转换、环节或组件框。修改后旧预览失效，必须重新生成。只有流程和全部环节重新确认后，才能显式点击“导出到飞书”并进入用户授权。

## 9. 待确认与质量门槛

### 9.1 分级导出门槛

以下核心字段未确认时阻止导出：环节顺序、入口、出口、关键转换来源和目标、触发类型、关键结果状态、代表截图缺失和流程断裂。

动效细节、弱网反馈、异常文案等非核心信息可以保留“待确认”，在预览和正文待确认区域集中提示，不阻止导出。

### 9.2 AI 草稿质量

“模型返回了内容”不等于成功。进入审核工作台前至少验证：

- 环节有可理解名称和目标。
- 关键转换具有来源、触发、响应和结果。
- 组件/区域不是整批空白或“未知待确认”。
- 截图顺序已用于建立默认流程关系，同时点击、动画结束、系统事件等触发方式没有仅凭顺序臆断。
- 点击转换存在可见目标或明确标记待补框。
- 自动转换没有被写成点击。

未达到阈值时任务显示“分析未达标”，提供重试或重新分析，不生成大量空白审核项。

### 9.3 来源等级

每条结论保留 `observed / inferred / unknown`、来源截图、置信度和人工确认状态。人工确认不改变原始来源等级，只表示用户接受该策划结论。

## 10. 保存、冲突与恢复

- 字段失焦、下拉切换和拖拽结束时自动保存。
- 每个环节显示保存中、已保存、保存失败和已确认状态。
- 保存失败保留本地修改，禁止确认；恢复连接后可重试。
- AI 重分析只产生建议值，不覆盖人工修改和已确认值。
- 编辑操作使用修订版本检测冲突；旧版本保存失败时显示冲突字段并保留双方值。
- 任务历史保存共享审核模型、编辑历史、代表图映射和确认进度。

## 11. 响应式与无障碍

- 桌面端使用全宽工作台；素材抽屉不挤压主流程。
- 小屏幕只允许流程泳道容器内部横向滑动，整页不得横向滚动。
- 环节视图在小屏幕切换画面和规则，不强行并排。
- 交互热区不小于 44×44px，边框和编号不能只靠颜色表达选中状态。
- 拖拽排序同时提供按钮；框选对象可通过 Tab 切换和 Delete 删除。
- 所有保存、错误、确认和失效变化使用可读状态文本与 `aria-live` 提示。

## 12. GVE16 正文映射

正文继续对齐 `TVnd...`，至少包含：定位说明、需求概览、UE 流转图、完整交互流程、分环节规则、待确认项、状态与异常和验收项。

- 全流程泳道和 `transitions` 生成完整交互流程。
- 环节小循环、区域规则和组件状态生成分环节规则。
- `crossStateConstraints` 和非核心未知项生成黄色重点说明及正文待确认内容。
- 每个环节和组件生成可测试的验收条目，不只输出通用口号。
- UE 画板已有截图时，正文不重复生成截图或证据帧图片区。

## 13. UE 画板映射

- 页面、弹窗和功能模块使用真实 Section。
- 每个环节使用能够解释进入、变化或结果的已确认代表图；不上传全部截图。
- 红色编号与旁侧规则严格一一对应，且不遮挡关键 UI。
- 跨状态约束、异常和待确认项使用浅黄色说明。
- 前进/打开使用带标签实线直箭头；返回/关闭使用带标签虚线直箭头。
- 自动转换使用明确标签，不生成点击锚点。
- 当前页内部状态变化保留在所属 Section 内，不误建新页面。

飞书发布顺序保持：创建正文 → 回读真实画板 token → 写入结构 → 上传白板作用域代表图 → 增量写入图片节点 → 预览验收 → raw 验收。失败重试复用原文档和检查点。

## 14. 错误处理

- 无候选转换：允许标记为流程终点、当前页状态环节或分析未达标，不能自动补一条点击跳转。
- 候选目标不存在：阻止流程确认并定位该转换。
- 组件框损坏或越界：恢复最后有效坐标并提示。
- 删除存在引用的对象：列出关联转换，由用户选择取消删除或同步解除绑定。
- 代表图失效：阻止环节确认和导出。
- 预览版本过期：禁用飞书导出并要求重新生成。
- 飞书授权或媒体失败：保留文档、画板和媒体检查点，允许继续重试，不重复建文档。

## 15. 测试与验收

### 单元测试

- 稳定 ID、显示编号重排和归一化坐标。
- 环节/转换/区域引用完整性。
- 触发与结果类型校验。
- 确认失效、核心阻断和非核心待确认规则。
- 撤销/重做与人工值保护。

### API 与持久化测试

- 共享审核模型的加载、补丁保存、版本冲突和历史恢复。
- 流程确认、逐环节确认和预览版本门槛。
- AI 建议不会覆盖人工值。

### 浏览器测试

- 上传后进入全流程视图。
- 候选转换筛选、转换切换、点击锚点定位和自动转换无锚点。
- 环节排序、组件框创建/移动/缩放、编号和规则同步选择。
- 保存失败、撤销/重做、刷新恢复和错误回跳。
- 桌面全宽布局、移动端内部滚动及画面/规则切换。

### GVE16 与飞书合同测试

- 正文章节、内容映射和无重复截图。
- 代表图去重、全局连续编号和黄色说明。
- Section、实线/虚线 connector、图片 token 和非零尺寸。
- 预览与 raw 双验收；不合格不得报告成功。

## 16. 完成定义

一期只有同时满足以下条件才算完成：

1. 用户能从 AI 草稿审核并确认完整大流程。
2. 每个环节形成可审核的小循环，并拥有必要的代表状态图。
3. 点击型、自动型、状态型和终点型转换不会互相混淆。
4. 组件框、点击锚点、红色编号和规则绑定稳定可恢复。
5. 核心未知项阻止导出，非核心未知项正确保留。
6. 刷新、历史恢复和 AI 重分析不丢失人工内容。
7. 导出预览与最终飞书正文、UE 画板使用同一份已确认模型。
8. 飞书预览和 raw 验收同时通过，且只包含必要代表图。
