# GVE16 两画板交互交付设计

日期：2026-07-28  
状态：待用户书面确认  
分支：`codex/gve16-calibration`

## 1. 需求基线

交互阶段以飞书 Wiki `ZsTVw7lTEi9rErknL9bcRfFunei` 的 `UE流转图` 为最新标准。2026-07-28 读取到的文档版本为 revision 40：

- `UX设计(ux做)` 已使用删除线标记，不属于当前交互交付。
- `策划草图` 是完整交互说明画板。参考画板包含 146 个节点：58 个截图、54 个复合形状、30 条连接线、4 个黄注记。
- `竞品参考` 是纯参考截图画板。参考画板包含 26 个图片节点，没有规则文字或连接线。

因此，新任务的交互环节只审核和导出 `策划草图` 与 `竞品参考`。叙事、引导、红点提示及 UX 设计不再作为当前交互阶段的独立审核步骤、导出章节或导出门禁。

## 2. 目标与非目标

### 目标

1. 审核路径固定为：素材导入 → 整体流程 → 环节 → 组件 → 两画板预览 → 飞书导出。
2. `策划草图` 自动从已确认的流程、环节、组件、状态和跳转关系生成。
3. `竞品参考` 使用用户独立上传的多张参考图片，保持文件名与顺序。
4. 飞书正文中的 UE 流转图只嵌入两个原生画板，顺序固定为 `策划草图`、`竞品参考`。
5. 竞品参考为空时仍允许导出，画板显示黄色 `待补充`，不产生 blocker。
6. 历史任务继续可读取，避免旧任务因字段或发布记录变化而损坏。

### 非目标

- 不生成或导出 `UX设计` 画板。
- 不在交互阶段审核或导出叙事、引导、红点提示三个规则域。
- 不把全部帧、证据帧或竞品截图混入策划草图。
- 不为旧版与新版增加用户可见的模式开关。
- 不删除历史任务中已经存在的 legacy 数据。

## 3. 产品流程

### 3.1 审核顺序

1. **整体流程审核**：确认截图顺序、主要环节和环节间跳转。
2. **环节审核**：逐环节确认代表截图、进入方式、退出方式和状态变化。
3. **组件审核**：在代表截图上确认组件框、编号、操作、反馈和目标状态。
4. **两画板预览**：
   - 策划草图：只读自动生成预览，显示代表截图、组件编号、规则说明、跳转/返回连线和待确认黄注记。
   - 竞品参考：显示独立素材池，支持多图上传、排序、移除、缺失恢复和失败重试。
5. **飞书导出**：确认当前 review revision 后创建正文与两个原生画板。

规则域审核视图从新任务导航和确认链中移除。组件确认完成后直接进入两画板预览。

### 3.2 空竞品状态

- 竞品参考是可选输入。
- 没有素材时显示 `待补充`，仍允许确认预览与导出。
- 飞书竞品画板必须真实存在，但只包含一个黄色 `待补充` 说明节点，不包含图片节点。

## 4. 数据与兼容策略

### 4.1 Active 数据

新任务只主动读写：

- 已有流程、环节、组件、状态与跳转数据。
- `referenceBoards.planning`：由确认后的 review model 自动生成，不接受用户上传。
- `referenceBoards.competitor`：用户上传的独立图片资产及其稳定 ID、顺序、相对路径和状态。
- 发布记录中的 `planning`、`competitor` 两个 board checkpoint。

### 4.2 Legacy 数据

以下字段继续容错读取，但新任务不展示、不修改、不作为 gate、不导出：

- `ruleDomains`
- `referenceBoards.ux`
- 旧发布记录中的 `ux` checkpoint
- 旧规则域确认状态和对应建议数据

保留 additive backfill 与 schema version `2.0`，不做破坏性 schema migration。历史任务打开后，其 legacy 数据原样保留；任何新保存操作都不得主动清空这些字段。

### 4.3 门禁

预览和导出只检查：

- 流程已确认。
- 所有环节已确认。
- 所有组件已确认。
- 当前 review model 无损坏的流程/环节/组件引用。
- 没有进行中的竞品上传或失败后尚未处理的素材操作。

不再检查 `RULE_DOMAINS_NOT_CONFIRMED`，也不要求 UX 或竞品至少有一张素材。

## 5. 两画板合同

### 5.1 策划草图

- 使用真实 Feishu Section 划分功能模块。
- 只使用每个已确认环节/状态的代表截图。
- 截图上显示红色编号，旁侧规则文字使用相同编号。
- 规则粒度覆盖：当前状态、用户操作、触发条件、系统反馈、操作后状态、分支/异常及去向。
- 视频或截图没有明确展示的信息统一写 `待确认`，不虚构参数。
- 前进/打开使用实线 straight connector；返回/关闭使用虚线 straight connector。
- 跨状态限制、异常和未决项使用黄色注记。
- 禁止加入竞品图片、全部帧或额外证据帧。

### 5.2 竞品参考

- 只使用 `referenceBoards.competitor.assets` 中状态为 ready 的图片。
- 保持用户确认后的顺序，并在图片附近显示原文件名。
- 不生成组件编号、规则说明或流程连接线。
- missing/failed 素材不生成图片节点；画板增加黄色缺失说明。
- 无 ready 素材时只显示黄色 `待补充`。
- 禁止回退到策划截图或 UX 素材。

### 5.3 正文与嵌入顺序

UE 流转图章节只包含：

1. `策划草图` + 原生 whiteboard
2. `竞品参考` + 原生 whiteboard

交互阶段不额外生成叙事、引导、红点提示章节，不重复放置画板里已经出现的截图。

## 6. 发布与恢复

- 发布器按 `planning`、`competitor` 两个 key 保存结构、媒体和 raw/preview 验收 checkpoint。
- 任一画板失败时，只重试失败画板，不重写已通过的画板或正文。
- 旧单画板 checkpoint 继续迁移到 `planning`。
- 旧三画板记录中的 `ux` 只保留兼容读取，不参与新发布完成度计算。
- 同一 request ID 重试必须复用原文档和原画板，不创建重复文档。
- 公开 API 只返回文档 URL 和可理解状态，不暴露 document/whiteboard/media token、绝对路径、CLI 输出或凭证。

## 7. 错误与恢复

- revision 冲突：重新加载 canonical review model，提示用户基于最新版重试。
- 竞品上传失败：保留 failed/retry 状态，阻止当前预览确认，重试成功后解除。
- 本地竞品文件丢失：刷新为 missing，清除过期 preview revision，但不阻止最终导出。
- 策划草图编译失败：阻止导出并返回到对应流程/环节/组件修复，不使用其他图片兜底。
- 飞书局部发布失败：保留成功 checkpoint，继续原文档的局部恢复。

## 8. 测试与验收

### 自动化测试

- 新任务审核路径不出现 rules 或 UX 步骤，组件确认后进入两画板预览。
- legacy `ruleDomains`、`referenceBoards.ux` 数据经打开和保存后仍原样保留。
- export gate 忽略 rules confirmation、UX 空状态和竞品空状态。
- 两画板顺序固定，策划草图无竞品图，竞品参考无策划图。
- 空竞品生成黄色 `待补充` 且零图片节点。
- publisher 两板独立 checkpoint、局部恢复、legacy planning 迁移和公开响应脱敏。

### 浏览器验收

- 移动端完成：整体流程 → 环节 → 组件 → 两画板预览。
- 页面没有规则域 tab、UX 上传入口或竖排长文本。
- 竞品多图上传、排序、删除、满额缺失替换和失败重试可用。
- 空竞品可以直接进入预览并导出。

### 飞书验收

- 文档 UE 流转图只出现两个原生画板。
- 策划草图包含 Section、代表截图、组件编号、规则文字、straight 连线和黄注记。
- 竞品参考只包含按序截图和文件名；空状态只含黄注记。
- 两板 preview 与 raw 节点同时通过检查后才报告发布成功。
