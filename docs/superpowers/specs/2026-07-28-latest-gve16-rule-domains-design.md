# 最新 GVE16 三画板与规则域审核设计

日期：2026-07-28  
状态：设计已确认，等待书面规格复核

## 1. 目标

在现有“全流程审核 → 环节/组件审核 → 导出预览”基础上，补齐最新版 GVE16 交互策划范围：UE 章节的 `UX设计`、`策划草图`、`竞品参考` 三个原生画板，以及第 9 章叙事、第 11 章引导、第 12 章红点提示。

策划草图继续由已确认审核模型自动生成；UX 与竞品只接收用户明确提供的可选素材。素材未展示或未提供时保留“待确认/待补充”，不得由 AI 编造。

## 2. 审核流程

审核步骤调整为：

`AI 草稿 → 全流程审核 → 流程确认 → 环节/组件审核 → 环节全部确认 → 规则域审核 → 规则域确认 → 导出预览 → 飞书导出`

规则域中的待确认信息不阻止导出，但用户必须显式确认已经审核三类规则。修改规则域后解除规则域确认和旧导出预览；修改流程或环节时继续按现有规则解除其下游确认，同时解除规则域确认。

## 3. 单一审核模型

在现有 `reviewModel` 增加两个集合，所有视图继续读写同一模型。

### 3.1 `ruleDomains`

```json
{
  "narrative": [],
  "guidance": [],
  "redDots": [],
  "confirmation": {
    "confirmed": false,
    "confirmedRevision": null
  }
}
```

所有规则项共享：稳定 ID、标题、绑定环节 ID、可选截图 ID、来源等级、置信度、人工修改字段、AI 建议、确认状态和待确认原因。引用的环节、截图或组件必须存在。

叙事项另外保存：触发场景、触发节点、呈现内容、播放完成后的后续流转。

引导项另外保存：触发范围与次数、前置条件、有序步骤、每步指向组件、提示文案、完成去向。步骤支持增删、排序和绑定组件。

红点项另外保存：显示条件、消去条件、有序穿透路径。路径从最终操作点逐层指向上层入口，每一层可绑定环节或组件；断裂引用属于导出阻断错误。

当某一规则域没有可确认内容时，保留空集合并在视图/正文显示“本次素材未展示，待确认”，不生成伪规则项。

### 3.2 `referenceBoards`

```json
{
  "ux": {"assets": [], "status": "pending"},
  "planning": {"source": "confirmed_review_model"},
  "competitor": {"assets": [], "status": "pending"}
}
```

UX 与竞品支持独立多图上传、自然排序、手动调整和删除。素材不参与主流程视觉分析，不进入主截图集合，不生成环节，不进入策划草图代表帧选择。每项保存文件名、顺序、相对路径、尺寸和所属画板。

UX 或竞品没有素材时允许导出，画板只显示“待补充”，不得复用策划截图冒充。

## 4. 规则域审核界面

规则域审核位于环节全部确认之后，采用 `叙事 / 引导 / 红点提示` 三个页签。

- 页签顶部显示规则数量、待确认数量和当前保存状态。
- 左侧为规则列表，支持新增、删除、排序和切换；右侧一次只编辑一条规则，避免纵向长表单。
- 环节、截图和组件使用可搜索选择器；组件选项随绑定环节过滤。
- 引导步骤和红点路径使用有序卡片，提供拖拽和等价的上移/下移按钮。
- 空域显示明确空状态、“本次素材未展示，待确认”和“新增规则”按钮。
- 三个页签都访问过且保存成功后，用户可以确认规则域；确认表示已审核，不表示所有未知项已补齐。

桌面端列表与编辑区并排；移动端使用“列表 / 编辑”页签。触控目标不小于 44×44px，排序和状态变化具备文本反馈与 `aria-live`。

## 5. 三画板素材界面

在规则域审核页下方提供“UE 三图准备”区域：

- `UX设计`：可选上传，展示素材顺序和待补充状态。
- `策划草图`：只读显示将由已确认模型生成，不接受手工替换结构。
- `竞品参考`：可选上传，展示素材顺序和待补充状态。

UX/竞品上传失败只影响对应素材保存，不污染主审核模型。未保存素材禁止立即导出；没有素材本身不阻止导出。

## 6. 导出预览与门槛

导出预览新增：

- 三个画板的状态、素材数量和策划草图代表帧数量。
- 叙事、引导、红点规则数量及待确认数量。
- 规则域确认状态和当前修订是否匹配。

以下情况阻止导出：规则域未审核确认、引用不存在、引导步骤组件引用损坏、红点穿透路径引用断裂、素材仍在上传或保存失败、预览版本过期。

以下情况不阻止导出：某规则域完全未展示、规则内容仍有非结构性待确认、UX 或竞品没有素材。

## 7. 飞书正文映射

正文始终保留以下章节：

- 第 9 章叙事：按规则项呈现触发场景、触发节点、内容和后续流转；空域写“本次素材未展示，待确认”。
- 第 11 章引导：按规则项呈现触发范围/次数、条件、步骤、指向组件、文案和去向；空域写同一待确认说明。
- 第 12 章红点提示：按规则项呈现显示条件、消去条件和完整穿透路径；空域写同一待确认说明。

章节编号与现有正文其他章节统一由渲染顺序决定，内部稳定 ID 不出现在正文。UE 画板已有截图时正文继续不重复图片。

## 8. 飞书三画板映射

UE 流转图章节嵌入三个独立原生 whiteboard 块：

1. `UX设计`：按用户素材顺序排布；无素材时写“待补充”。
2. `策划草图`：沿用现有 Section、代表帧、红色编号、规则说明、黄色约束和实/虚线连接器生成逻辑。
3. `竞品参考`：按用户素材顺序排布；无素材时写“待补充”。

发布器需要保存三个画板 token 和各自媒体映射。结构写入后不得再次 overwrite；每个画板分别执行预览与 raw 验收。任一实际写入失败时复用原文档和对应画板检查点继续，不新建重复文档。

## 9. 保存、历史与 AI 建议

- 新集合沿用修订版本、原子操作、撤销/重做、保存状态和历史任务恢复。
- 人工修改优先；重分析只生成建议，不覆盖规则域人工值或参考画板素材。
- 规则项增删、排序、字段修改和绑定修改进入编辑历史。
- 参考素材上传不进入文本撤销栈，但删除前可取消；保存完成后记录在任务历史。

## 10. 错误与空状态

- 模型未识别规则：保留空域和待确认说明，不把“unknown”批量生成为规则。
- 绑定对象被删除：解除规则域确认并标出损坏引用；用户重新绑定或删除规则后才能导出。
- 红点路径只有一层：允许保存，但必须存在有效最终操作点；是否需要上层穿透可保留待确认。
- UX/竞品素材损坏：不回退为策划截图；显示失败文件并允许重传。
- 三画板部分发布成功：保存每个 token/媒体进度并从失败画板续传。

## 11. 测试与验收

后端模型与服务测试：默认空域、稳定 ID、字段校验、引用完整性、规则域确认失效、修订冲突、撤销/重做、历史恢复和 AI 建议保护。

前端测试：三页签、空状态、规则增删排序、绑定过滤、引导步骤、红点路径、保存状态、规则域确认、移动端列表/编辑切换和键盘操作。

渲染测试：三个章节始终存在；空域使用标准待确认文本；有数据时字段完整且不暴露内部 ID；三块 whiteboard 顺序固定。

发布测试：三个画板 token 独立回读、素材不串板、策划代表帧不进入 UX/竞品、预览/raw 分板验收、失败续传不重复建文档。

端到端验收：从已确认环节进入规则域审核，确认空域允许导出；新增叙事、跨步骤引导和红点穿透路径后刷新恢复；导出预览正确计数；最终飞书文档包含三画板与三章节。

## 12. 非目标

- 不自动生成 UX 稿或竞品截图。
- 不把 UX/竞品素材纳入视觉分析、主截图上限或策划代表帧。
- 不复刻 GVE16 的其他玩法、商业化或数值章节。
- 不在本次扩展中实现通用自由画板或复杂图像编辑器。

## 13. 完成定义

1. 三类规则均可审核、保存、恢复和确认，空域不会产生伪内容。
2. 非结构性待确认与缺少 UX/竞品素材均允许导出。
3. 损坏引用、未确认规则域和过期预览可靠阻止导出。
4. 飞书正文始终包含第 9、11、12 章及正确的空状态。
5. UE 章节包含三个独立原生画板，素材与 token 不串用。
6. 策划草图继续只使用已确认代表帧，无重复证据图片区。
7. 三画板分别通过预览和 raw 验收，失败可从检查点恢复。
