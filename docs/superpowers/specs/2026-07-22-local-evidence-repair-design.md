# 局部证据补取与重新解读设计

## 1. 背景与目标

“需要重点检查”已经能从 138 张关键帧中筛出约 22 张，但低把握帧仍可能只显示“画面信息不足”。策划需要手动拖动视频、寻找前后画面，再判断缺少的是操作、结果、文字还是状态变化。

本功能将这个过程收敛为一个局部闭环：说明具体问题 → 一键补取前后画面 → 只分析当前局部证据 → 安全合并新结论 → 重新判断是否仍需检查。

## 2. 核心原则

- GVE16 关键帧编号、主时间线和审核总数保持稳定。
- 补取画面是当前关键帧的辅助证据，不进入主关键帧列表。
- 只重新分析当前证据组，不重新运行整个场景或整段视频。
- 人工修改优先于模型建议，任何人工内容不得被静默覆盖。
- 沿用任务当前配置的兼容视觉模型接口，不绑定千问。
- 所有提示使用策划能直接理解的中文，不暴露内部字段名或技术错误。

## 3. 重点检查原因

每帧最多显示三个原因，优先级如下：

1. `前后结论不一致`：当前帧与相邻证据的操作、状态或结果冲突。
2. `缺少玩家操作` / `缺少用户操作`：没有直接看到或说明操作。
3. `玩法目的不明确` / `当前界面不明确`：缺少当前玩法阶段或页面用途。
4. `关键操作可能发生在两帧之间`：当前帧继承场景概括，未经过独立逐帧分析，或相邻主帧时间间隔过大。
5. `操作结果没有画面证明`：有操作但缺少系统响应或操作后状态。
6. `界面文字看不清`：视觉分析明确报告文字不可读、模糊或被遮挡。
7. `画面被特效或弹窗遮挡`：视觉分析明确报告主体或关键信息被遮挡。
8. `画面信息仍然不足`：低把握但没有更具体、可验证的原因。

原因由两类信号组成：

- 确定性规则：关键字段缺失、冲突标记、继承场景摘要、缺少操作后状态。
- 模型返回的受控信号：`text_unreadable`、`visual_occlusion`、`action_between_frames`、`result_not_shown`、`state_chain_broken`。后端只接受白名单值，并映射为中文。

普通 `unknowns` 内容本身不进入重点检查，避免再次把全部 138 帧都标为重点检查。

## 4. 辅助证据组

### 4.1 取帧范围

点击“补取前后画面”后，以当前关键帧时间点为中心，默认取：

- 当前时间前 1 秒
- 当前时间前 0.5 秒
- 当前时间
- 当前时间后 0.5 秒
- 当前时间后 1 秒

时间点在 `[0, 视频时长]` 内裁剪并去重。当前主帧已有原图时直接复用，不重复写入。

### 4.2 存储

辅助图片保存在任务目录的独立 `supplemental/` 目录。当前帧记录一个 `supplementalEvidence` 对象：

```json
{
  "status": "ready",
  "samples": [
    {"timestamp": 12.5, "imageUrl": "/artifacts/<job>/supplemental/...jpg"}
  ],
  "updatedAt": "ISO-8601"
}
```

辅助证据不进入 `job.frames`，因此不改变关键帧数量、确认数量、场景帧列表或 GVE16 Evidence ID。

相同关键帧再次补取时复用时间戳一致的已有图片；用户主动点击“重新补取”时，仅补充缺失文件并重新分析。

## 5. 局部重新解读

后端增加一个当前帧局部重解读入口。它执行：

1. 校验任务、源视频和目标关键帧。
2. 生成或复用五帧辅助证据。
3. 使用目标帧所在场景摘要作为背景，但不改写场景摘要。
4. 将五帧按时间顺序发送给当前配置的视觉模型。
5. 要求模型返回：目标帧的新分析字段、受控检查信号、每项结论引用的辅助时间点。
6. 保存建议、辅助证据和运行状态。
7. 重新运行质量审计和策划案生成，但只在用户采用建议后改变正式分析字段。

局部请求是异步任务。前端轮询现有任务状态，展示“正在补取画面”“正在重新解读”“已生成建议”或失败状态。

## 6. 人工修改保护与合并

### 6.1 修改来源

通过人工审核接口保存过且内容不同于上次模型结果的字段视为人工修改。后端为这些字段保存 `humanEditedFields`，不依赖前端临时状态。

### 6.2 合并规则

- 未人工修改的字段：局部分析结果自动写入正式分析。
- 已人工修改且新建议相同：保持当前内容，不显示冲突。
- 已人工修改且新建议不同：不覆盖，写入 `analysisSuggestion`，前端显示“当前内容 / 新分析建议”。
- 策划点击“采用建议”后，该字段写入正式分析，同时仍标记为人工确认结果。
- 策划点击“保留当前内容”后清除该字段建议，保留当前值。

任何失败都不得清空现有分析、人工修改或已保存的辅助图片。

## 7. 前端交互

重点检查原因区域增加一个主按钮：`补取前后画面`。

状态顺序：

1. 默认：显示原因、核对建议和补取按钮。
2. 处理中：按钮禁用，显示当前阶段；当前帧仍可阅读，不遮挡表单。
3. 已完成且无冲突：字段原位更新，原因重新计算。
4. 存在人工内容冲突：在对应字段下方显示建议卡，提供`采用建议`与`保留当前内容`。
5. 原因全部消失：当前帧保持不动，显示“这一帧已不再需要重点检查”。
6. 仍需检查：保留具体原因，并显示五张辅助画面的时间顺序缩略图。
7. 失败：显示可理解的错误和`重新尝试`，不影响其他帧审核。

辅助证据缩略图支持点击后在主预览区查看，并可定位原视频时间点。按钮和缩略图满足键盘访问、可见焦点和至少 44×44 像素触控区域。

## 8. API 与状态

建议新增接口：

- `POST /api/jobs/{job_id}/frames/{frame_id}/supplement-and-reanalyze`
- `POST /api/jobs/{job_id}/frames/{frame_id}/suggestions/{field}/accept`
- `DELETE /api/jobs/{job_id}/frames/{frame_id}/suggestions/{field}`

局部任务状态保存在目标帧的 `supplementalEvidence.status`：`idle | extracting | analyzing | ready | failed`。错误对外返回策划可理解的消息，详细技术信息只保存在任务日志中。

同一帧已有进行中的局部任务时返回 409，防止重复调用。不同帧可排队，但沿用现有后台执行器，不增加新队列依赖。

## 9. 失败与边界处理

- 视频开头或结尾：裁剪时间并去重，至少保留两个不同时间点；不足两个时返回“视频片段过短，无法补取更多画面”。
- 源视频不存在：保留原任务，提示源视频不可用。
- 模型未配置：辅助帧仍保存，提示填写视觉模型配置后重试分析。
- 模型返回非法信号：忽略非白名单信号，保留通用原因。
- 模型超时或响应无法解析：状态为失败，保留现有分析和图片。
- 重复请求：复用已有辅助图片，只重新调用分析。
- 任务归档：允许只读查看已有辅助证据，不允许启动新分析。

## 10. 测试与验收

### 自动化测试

- 原因分类的优先级、白名单、去重、三项上限以及玩法/交互用语。
- 五个时间点在视频首尾的裁剪、去重与稳定排序。
- 相同时间点图片复用，不产生重复文件。
- 局部分析不修改场景、主帧数量、主帧 ID 或无关帧。
- 未人工修改字段自动更新；人工修改字段只生成建议。
- 采用与拒绝建议的持久化行为。
- 模型失败、源视频缺失、重复运行和归档任务的响应。

### 页面验收

- 真实 138 帧任务仍显示 138 帧和约 22 个重点检查项。
- F0002 可补取最多五张辅助帧，缩略图按时间排列。
- 处理中有明确反馈且按钮不可重复点击。
- 新结论不会覆盖手动修改内容。
- 问题解决后当前帧不跳转，并显示完成提示。
- 桌面端与窄屏均无横向滚动；键盘可操作按钮和缩略图。

## 11. 不在本次范围

- 不改变全片初次抽帧策略。
- 不把辅助帧加入 GVE16 Evidence 表或人工确认总数。
- 不自动批量处理全部 22 帧，避免不可控的视觉模型费用。
- 不重新分析整个场景或整段视频。
