# 精简交互审核设计

## 目标

让策划先用 3–7 个功能环节确认整体流程，再逐环节审核代表画面与关键组件。界面以中文、摘要和按需展开为主，不把模型字段直接铺成表单墙。

## 流程归并

- 顶层环节按“功能变化”划分，不按截图数量划分。
- 同一页面、同一交互目标或同一玩法阶段的连续画面合并为一个环节。
- 武器选择的展开、选择和结果画面归入同一环节；普通战斗的连续表现归入同一环节。
- Boss 预警、Boss 战斗、胜利结算等目标明显不同的状态保留为独立环节。
- 分析模型首先输出 3–7 个环节；若结果仍超过 7 个，后端对相邻同类环节进行二次合并。
- 每个环节保留 1–3 张代表图，其余素材进入“查看全部截图”，不占用顶层流程节点。
- 素材顺序始终保留，归并不得打乱截图或视频时间顺序。

## 页面审核交互

- 顶部只显示短标题，例如“普通战斗”“武器选择”“技能三选一”。
- 点击标题后必须同时切换当前环节、代表图、标注框和右侧摘要。
- 切换环节时清除上一环节的图片、区域和组件选择；默认选中新环节第一张代表图。
- 当前标题有明确选中态，并保留键盘可达与焦点反馈。

## 右侧摘要

默认只显示一张中文摘要卡：

1. 页面/环节名称
2. 当前目标
3. 如何进入
4. 用户操作或自动触发
5. 系统反馈与结果
6. 关键组件

内部字段名不得直接展示。`unknown` 统一显示为“待确认”。

组件详细编辑默认收起。策划点击画面编号框或关键组件条目后，只展开当前组件的小型编辑区；不同时铺开全部组件状态。

## 数据与兼容

- 飞书交付仍使用标准 GVE16 环节、代表图、区域、组件和流转数据结构。
- 归并发生在审核模型生成阶段，避免仅在前端隐藏节点而让导出继续保留冗余环节。
- 已生成任务重新生成审核模型后应用新归并规则；已人工确认的数据不做静默改写。
- 未识别的触发方式保留“待确认”，不阻止策划确认环节顺序。

## 验收标准

- 任一新任务的顶层流程为 3–7 个功能环节。
- 点击任一环节标题后，代表图与摘要同步切换，不残留上一环节选择。
- 页面审核默认没有英文内部字段和成组展开的组件表单。
- 组件详情只在选中对应编号或条目后出现。
- 代表图、素材顺序、组件标号以及 GVE16 导出数据保持完整。
- 自动化测试覆盖流程上限、相邻同类归并、标题切换重置和中文摘要显示；浏览器验证覆盖实际点击切换。
