# 长视频关键帧快速筛选设计

## 目标

让用户在上百张关键帧中快速进入目标场景，并集中检查有风险或尚未确认的内容，同时保持现有单帧审阅体验。

## 审阅工具条

工具条位于单帧审阅器导航栏下方、截图和说明上方，包含：

- 场景选择：列出全部场景及其时间范围；选择场景后打开该场景时间最早的一帧。
- 帧筛选：全部、需要重点检查、视频没有明确展示、尚未人工确认。
- 结果计数：筛选时显示“筛选后第 3 / 18 帧 · 全部 138 帧”；未筛选时显示“第 3 / 138 帧”。

工具条不新增侧栏，不压缩截图和文字说明区。移动端允许场景选择和筛选控件换行，但不得产生横向滚动。

## 筛选含义

- 全部：按时间顺序显示所有关键帧。
- 需要重点检查：模型判断把握较低，或当前帧被质量检查标为存在冲突、证据不足。
- 视频没有明确展示：证据等级为“未知待确认”，或模型明确记录视频缺失的信息。
- 尚未人工确认：用户尚未勾选“确认这一帧可纳入策划案”。

界面不使用“低置信度”“冲突检测”等模型或研发术语。

## 导航规则

- 左右按钮和键盘方向键只在当前筛选结果中移动。
- 第一条和最后一条筛选结果分别禁用上一帧和下一帧。
- 切换筛选后，优先保留当前帧；若当前帧不符合新条件，则打开筛选结果中的第一帧。
- 筛选结果为空时保留工具条，显示“当前没有需要检查的关键帧”，不显示失效的单帧表单。
- 选择场景时保留当前筛选；若该场景没有符合条件的帧，则打开该场景第一帧，并把筛选恢复为“全部”。
- 从时间轴、证据点、场景列表或待审核问题打开不符合当前筛选的帧时，自动恢复为“全部”，再定位目标帧。

## 数据与兼容

- 复用 `state.frames`、`state.sceneGroups`、`confidence`、`evidenceLevel` 和 `confirmed`，不改变后端任务结构。
- 新增一个纯前端筛选状态，默认值为“全部”。
- 冲突标记存在时参与“需要重点检查”；旧任务没有冲突标记时仅依据判断把握和证据等级。
- 筛选不改变保存、确认和最终策划案数据，只改变当前浏览集合。

## 无障碍与反馈

- 场景和筛选控件均有可读标签。
- 筛选变化后通过现有播报区域说明结果数量和当前帧。
- 文本编辑时方向键仍只移动光标，不切换关键帧。
- 筛选状态不只依赖颜色，始终显示完整文字。

## 验收

- 138 帧任务可以按场景直接定位。
- 四种筛选结果与帧数据一致，筛选内左右切换不越界。
- 外部时间轴定位会自动退出不兼容筛选并打开正确帧。
- 筛选为空、切换模式、打开旧任务和移动端换行均可正常使用。
- 筛选和浏览不会丢失尚未保存的编辑内容。

## 范围外

- 不增加复杂搜索、标签系统或自定义筛选表达式。
- 不修改视频抽帧、模型判断和策划案生成逻辑。
- 不新增运行时依赖。
