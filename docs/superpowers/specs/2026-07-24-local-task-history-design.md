# 本机任务历史访问设计

## 目标

本机操作者通过 `127.0.0.1` 或 `localhost` 打开言灵镜瞳时，可以查看、刷新、打开和归档已有任务；通过局域网 IP 访问的体验者不能看到或枚举本机任务历史。

## 访问边界

- 本机访问：显示“任务历史”面板，页面初始化时自动加载最近 20 条未归档任务。
- 局域网访问：隐藏“任务历史”面板，不发起历史列表请求。
- 后端保护：历史列表和归档接口只接受 loopback 来源（IPv4 `127.0.0.0/8`、IPv6 `::1`）。非本机来源返回 `403`。
- 不受影响：局域网体验者仍可创建新任务、轮询自己当前页面持有 ID 的任务、审核当前任务和导出飞书文档。

## 前端流程

1. 初始化时依据 `location.hostname` 判断是否为本机访问。
2. 本机访问解除 `historyPanel.hidden`，绑定现有刷新、打开和归档交互，并调用现有 `loadJobHistory()`。
3. 局域网访问保持面板隐藏，也不请求 `/api/jobs`。
4. 历史读取失败时在历史面板内显示明确错误，不阻断上传和分析主流程。

## 后端流程

1. 增加一个只判断请求来源是否为 loopback 的小型共享函数。
2. `GET /api/jobs` 在读取任务列表前执行该判断。
3. 历史归档接口在修改任务前执行同一判断。
4. 保持单任务读取接口不变，避免破坏局域网任务轮询。

## 验证

- 前端单元测试：`127.0.0.1` 和 `localhost` 判定为本机；局域网 IP 判定为非本机。
- 前端契约测试：本机初始化显示并加载历史；局域网不显示、不加载。
- 后端测试：loopback 可列出和归档；非 loopback 请求得到 `403`。
- 回归测试：远程创建任务和按 ID 读取任务的接口保持可用。

## 非目标

- 不增加管理员密码、登录系统或新的历史数据库。
- 不按浏览器用户拆分任务所有权。
- 不改变任务文件的现有存储结构和归档语义。
