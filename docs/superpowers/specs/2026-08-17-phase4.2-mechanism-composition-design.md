# Phase 4.2 Mechanism Composition + Style Transfer

## Scope

Phase 4.2 generates a six-chapter reference sample only. It does not modify Rule, Gap, ChapterSchema, job state, P5/P6, EntityBuilder, or ParameterResolver.

## Public interfaces

- `compose_mechanism_blocks(chapter, approved_rules, reviewed_gaps, schema)`
- `render_mechanism_block(block, style_profile)`

## Data flow

`Approved Rule → Semantic Role Assignment → Mechanism Chain Partition → MechanismBlock → abstract organization rules → paragraph`

Semantic roles are assigned by ChapterType, SchemaSlot, and structured Rule fields. Keywords may not be the sole classifier. Rules may be stitched only when the schema declares the same content group or an explicit adjacency policy and their semantic keys remain individually traceable.

## MechanismBlock contract

Each block exposes `definition`, `trigger`, `condition`, `processing`, `state_change`, `result`, `exit_or_boundary`, `presentation`, `config_reference`, `ruleIds`, `factIds`, `evidenceIds`, `emptyFields`, `unabsorbedGapIds`, `stitchGroups`, and `status`.

Unsupported fields remain empty. Gaps never populate confirmed fields. Dynamic headings derive only from occupied SchemaSlots and existing mechanism semantics.

## Style permissions

The composer/renderer may use abstract organization rules: chapter-internal grouping, heading granularity, bullet density, rule stitching, contextual subject omission, mechanism-semantic subheadings, definition-before-detail, and lifecycle-after-main-behavior. Runtime code cannot read raw GVE16 sentences or project content.

## Acceptance

The six reference chapters are 载具移动、武器攻击、三选一、怪物攻击、关卡流程、结算. Output includes Approved Rule → MechanismBlock → final paragraph, used paradigms, empty fields, unabsorbed gaps, stitch provenance, partial/evidence-insufficient labels, traceability, and `unsupported semantic addition = 0`.
