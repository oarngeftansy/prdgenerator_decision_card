# “为什么需要重点检查”设计

## 目标

让策划在查看“需要重点检查”的关键帧时，直接知道问题在哪里、下一步该核对什么，不再逐项阅读字段寻找原因。

## 展示规则

- 在当前关键帧标题下方展示“为什么需要重点检查”。
- 每帧最多展示三个原因，按“前后结论冲突、缺少操作或场景信息、画面信息不足”的顺序排列。
- 原因使用策划能直接理解的中文，不展示 `low confidence`、字段名或模型内部错误。
- 原因同时给出简短的核对建议，例如“请回看前后 2–3 秒，确认玩家执行了什么操作”。

## 原因映射

- 存在跨帧冲突：`前后结论不一致`。
- 缺少 `userAction`：玩法模式显示`缺少玩家操作`，交互模式显示`缺少用户操作`。
- 玩法模式缺少 `gameState` / `what`：`玩法目的不明确`。
- 交互模式缺少 `what`：`当前界面不明确`。
- 判断把握为低：`画面信息不足`。

## 修改后的反馈

- 策划补全字段或调整判断把握后，原因立即重新计算。
- 原因全部消失时，当前帧保持不动，显示“这一帧已不再需要重点检查”。
- 不自动切换到下一帧，策划主动使用右箭头继续。
- 只有当前帧原本属于“需要重点检查”时才显示完成提示，普通帧不显示。

## 边界

- 沿用现有前端重点检查判定，不改变当前约 22 帧的筛选范围。
- 不把后端依赖缺失等技术告警混入逐帧原因。
- 不增加新的持久化字段或依赖。

## 验收

- 每一种重点检查条件都有通俗原因和核对建议。
- 同一原因不重复，最多显示三个。
- 补全缺失字段后，对应原因即时消失，当前帧不跳转。
- 全部原因消失后显示完成提示。
- 玩法与交互模式的操作、场景用语不同。
