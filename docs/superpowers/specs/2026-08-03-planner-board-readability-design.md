# 策划草图与环节命名可读性设计

## 目标

让交互审核工作台、策划草图和最终飞书文档使用同一套策划可读的环节名称与内容摘要，消除文字重叠、内部英文和无意义编号名称。

## 环节命名

- 环节名称由“玩家操作、系统反馈、操作结果”共同生成，优先描述玩家正在完成的事情。
- 名称控制在 12～18 个汉字内，不使用“确认第 N 步操作”“场景 N”“环节 N”等编号兜底。
- 证据不足时生成中性的动作名称并标记“建议核对”，不阻塞策划继续审核。
- 名称允许策划修改；修改后工作台、策划草图与最终飞书文档同步使用最新名称。
- 禁止输出内部角色值和分析英文，包括 `entry`、`result`、`component`、`damage numbers`。

## 策划草图结构

- 阅读顺序固定为：操作前 → 玩家操作 → 系统反馈 → 操作结果。
- 代表画面角色只使用“操作前”“操作后”等中文；非必要时不单独展示角色标签。
- 卡片标题最多两行，操作与反馈各最多两行；超长内容在草图中显示策划摘要，完整内容保留在文档正文。
- 卡片高度根据换行后的内容计算，同一组卡片底部对齐。
- 连线和回环线位于卡片内容区之外，不得穿过标题、说明或图片。
- 宽度不足时允许草图横向滚动，不压缩卡片导致文字重叠。

## 视觉与交互规则

- 风格路线：精炼极简 + 严格网格 + 策划工作台。
- 标题、操作、反馈使用稳定的三级文字层级；强调色只用于玩家操作与主流程箭头。
- 使用清晰边框和有效留白，不使用装饰性渐变、玻璃效果、重复圆角容器或无意义动效。
- 工作台中的环节名称编辑应即时保存，并在重新生成预览时反映到草图。
- 预览页不展示“非核心提醒”列表，也不展示 `STG-*`、`TRN-*`、`COMPETITOR_BOARD_PENDING` 等内部编号。
- 需要策划关注的信息仅在对应环节旁以中文“建议核对”显示。

## 生成玩法章节

- 点击“确认交互，生成玩法章节”后，按钮立即切换为“正在生成玩法章节”，并显示实际进度。
- 生成成功后自动进入“确认玩法目录”，不要求策划再次寻找入口。
- 生成失败时在按钮附近显示中文原因和“重新生成”，不得只在页面顶部或日志中显示通用错误。
- 后端保留可供前端展示的安全失败原因，不吞掉模型请求、返回格式或素材读取错误。
- 重复点击不得创建并行任务；运行中按钮保持禁用并明确显示当前状态。

## 数据流

1. 视觉分析生成场景事实。
2. 环节命名器根据事实生成策划动作名称和核对状态。
3. 审核模型保存名称，策划可编辑。
4. 规划模型复用审核后的名称。
5. 草图渲染器与飞书渲染器只读取规划模型中的统一名称。

## 异常处理

- 无法提取有效动作时使用“查看当前状态并继续操作”等中性动作名称，同时标记建议核对。
- 图片缺失时保留文字卡片并明确提示图片缺失，不让布局坍塌。
- 单段文本超限时进行中文语义摘要；不通过缩小字号容纳无限文本。

## 验收标准

- 截图中的两类复现案例不再出现任何文字重叠。
- 不出现 `entry`、`result`、`damage numbers` 或“确认第 N 步操作”。
- 不出现 `STG-*`、`TRN-*` 或其他内部提醒编号。
- 同一环节在工作台、草图和飞书文档中的名称一致。
- 长标题、长操作、长反馈以及缺图情况均有自动化测试。
- 真实任务预览可生成，主流程与回环线不遮挡文字。
- 点击生成玩法章节后必须有即时反馈；成功自动进入目录，失败原位提供中文重试入口。
