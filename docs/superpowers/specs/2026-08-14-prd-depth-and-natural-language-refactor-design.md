# 策划案深度与自然语言生成重构设计

## 目标

本次重构建立一套对多种玩法均有效的策划案生成规则，同时解决两个层面的问题：

1. 修复生成器的结构性缺陷，避免同一规则被重复写入状态、职责、反馈和表现等多个载体。
2. 将当前“一路狂飙”任务作为首个迁移样本，使正文的玩法深度、语言组织和图文排布达到 GVE16 样例中适用于本项目的颗粒度。

本次不以字数、章节数或表格数量作为完成标准。只有证据支持的规则闭环、自然的业务目录和可执行的制作信息可以进入正式正文。这套规则必须适用于移动、放置、随机、成长、战斗、背包、Buff、扫荡及后续新增玩法；具体领域模块只有在当前素材命中时才启用。

## 范围

### 生成器

- 规划模型中的正文、状态、运行职责、表现、参数、图解、截图和决策项各自承担唯一职责。
- 标题根据业务对象和实际机制生成，不使用统一章节模板。
- 样例知识只能提供问题清单和组织方法，不能自动成为当前项目事实。
- 正文输出增加重复、审核话术、模板标题、样例污染和浅层机制检查。
- 深度、语言、标题、载体和决策卡规则作为全局生成契约，不绑定具体项目名或玩法类型。

### 当前任务

- 重构载具、武器、局内升级、终极强化、武器抽取、怪物与关卡、结算等已识别机制。
- 将表现说明移至策划草图、局部截图或确有必要的战斗表现段。
- 将无法由当前素材唯一判断的关键规则转成决策卡。
- 保留当前截图中能够直接证明的可见状态，但截图数值不得冒充默认配置。

当前任务只是第一份回归样本，不得在通用逻辑中硬编码其章节名、截图 ID、对象名、数值或机制组合。

### 不在本次范围内

- 不把 GVE16 的背包、Buff、扫荡、商业化等未在当前素材中识别的系统写入正文。
- 不在未获得权威来源时伪造配置表名、字段名、概率、权重或公式。
- 本阶段不直接修改用户正在手工编辑的飞书文档；先保证网站预览和生成模型正确。

## 方案选择

采用“生成器根治 + 当前案例重构”。

只改当前文档无法阻止下一任务复发；只增加审核门禁又不能生成更好的正文。因此先修模型职责和质量门禁，再迁移当前任务。

## 模型职责

### 正文规则

正文只说明游戏如何运行，按适用情况覆盖：

- 触发和前置条件
- 读取的对象或数据
- 判断和执行顺序
- 状态修改和写回
- 玩家可操作内容
- 成功、失败和异常结果
- 保存、恢复、清除和重置范围

正文不得出现“截图只能证明”“当前项目应”“本节继续说明”“后续章节展开”等审核或编辑话术。

### 策划草图与截图

- 策划草图承载页面节点、玩家操作、跳转、暂停/恢复和可见状态关系。
- 局部截图紧跟它所证明的规则，说明可见状态或控件含义。
- 表现类信息原则上不在玩法正文重复；只有表现本身影响判断、时序或验收时才进入对应规则。

### 参数与配置

- 正文解释属性或参数的业务含义、参与判断的位置以及与其他属性的关系。
- 配置表承载值、单位、范围、权重、资源引用和查配关系。
- 权威配置名存在时，采用“业务名 → 表名/字段名”的就近映射。
- 没有权威配置名时，保留业务参数并创建决策项，不生成正式表名。

### 决策卡

仅在存在多种合理解释且素材不足以唯一判断时生成。每张卡包含：

- 具体问题
- 至少两个可执行选项
- 推荐项及理由
- 自己填写
- 暂时跳过
- 单选或多选限制
- 判断依据
- 应用后更新范围

未选择内容不得写成已确认结论。

## 自适应目录

目录以业务对象或实际机制命名。以下仅是当前任务根据现有证据形成的候选结构：

1. 玩法说明
2. 关卡流程
3. 载具
   - 移动与承伤
   - 载具等级（仅保留当前项目适用且有来源的内容）
   - 武器栏（仅保留当前项目适用且有来源的内容）
4. 武器
   - 攻击规则
   - 基础属性
   - 解锁与养成（仅在证据支持时出现）
   - 武器词条（仅在证据支持时出现）
5. 局内强化
   - 战斗等级
   - 三选一
   - 终极强化
   - 武器抽取
6. 怪物与关卡
   - 波次
   - 刷新
   - 移动
   - 攻击
   - 受击与死亡
   - 首领阶段
7. 战斗规则
   - 索敌与命中
   - 伤害计算
   - 伤害统计
8. 关卡结算

这不是通用固定模板。实现时根据每个任务的证据重新识别对象与机制，合并内容不足的小节，并删除不适用部分。其他玩法可以生成完全不同的一级目录和章节数量。

## 通用玩法适配

生成器维护领域问题库，但不维护通用固定目录。问题库按证据激活：

- 移动与空间：输入、坐标、边界、碰撞、停靠、恢复和非法位置回退。
- 放置与容器：资格、容量、占用、冲突、替换、合并和失败回退。
- 随机与刷新：进池、过滤、权重、去重、填位、暂存、确认、成本和重置。
- 战斗与投射物：索敌、释放、命中、伤害顺序、状态、死亡和归属。
- 成长与养成：解锁、消耗、升级、属性读取、不可逆和重置范围。
- Buff 与特殊效果：来源、目标、添加、生效、层数、刷新、移除和持续周期。
- 背包与格子：形状、旋转、坐标、占用、交换、保存和非法操作反馈。
- 关卡与波次：进入、场景、波次、刷新、转换、胜负、结算和重试。
- 扫荡与局外入口：资格、消耗、次数、奖励、失败返还和进度保存。

每个领域模块只有三种结果：`applicable`、`decision_required` 或 `not_applicable`。`not_applicable` 仅保存在审核数据中，不生成空章节；`decision_required` 生成决策卡，不生成确定正文。

## 机制深度要求

### 载具

检查自动推进、横向输入、操作结束位置、移动边界、停止和恢复、承伤、死亡、暂停影响和局内/活动生命周期。不能仅描述小地图、血条和 HUD。

### 武器与战斗

检查合法目标、索敌优先级、攻击前后状态、锁定和命中校验、冷却起算、弹道或范围判定、并发攻击、伤害归属和目标死亡。伤害规则在证据允许时说明闪避、格挡、减伤、元素修正、最低伤害、取整和死亡顺序。

### 三选一与随机机制

检查进池资格、过滤、权重、是否放回、同屏去重、填位顺序、候选不足、空结果、满级移池、暂存、确认、刷新成本、连续升级积压、写回和单局重置。未确认项必须进入决策卡。

### 终极强化

检查进入条件、与普通候选的关系、是否占候选位、重复或互斥、收益和代价的应用顺序、攻击形态变化及重置范围。

### 武器抽取

将滚动和跳过视为表现层；正文重点检查抽取池、消耗扣除点、结果生成时机、结果数量、重复处理、栏位满、跳过影响、断线恢复和写回。

### 波次、怪物和首领

检查波次开始/结束、怪物组顺序、间隔、刷怪点、相对位置、残留怪、下一波、首领切换、怪物移动/攻击状态、受击/死亡和首领胜负条件。

### 结算

检查成功与失败入口、统计口径、奖励来源、记录比较、双倍领取条件、扣次时机、重复领取、领取失败、离开和数据保存。

## 语言规则

- 标题优先使用对象或稳定业务动作，例如“载具”“武器栏”“三选一”“伤害计算”。
- 禁止用“命中、反馈与归集”“进入与生效”等抽象词组拼接标题。
- 句子优先采用“适用条件 → 动作 → 结果”，严格算法才编号。
- 平行规则使用项目符号；短规则与相邻机制合并。
- 删除不增加制作信息的“负责、承担、对应、相关、形成闭环”等套话。
- 表格已有的值不逐格改写成正文；正文只解释关系和用途。
- 审核结论、证据置信度和改善路径只存在于审核数据，不进入交付正文。

## 图文排布

- 流程图放在介绍触发的文字之后、分支和异常说明之前。
- 图后直接解释关键分支，不出现编辑说明。
- 截图位于它所证明的规则之后，使用业务化短标题。
- 正文、流程图、截图、参数表不重复承担相同信息。
- 历史或错误流程图必须通过规则版本和章节引用校验后才能进入预览。

## 实现结构

### 规划模型归一化

增加交付载体归一化步骤：

1. 将每条内容分配到唯一主要载体。
2. 对跨载体引用使用 ID，不复制正文。
3. 标记来源为当前素材、当前参考文档、已确认决策或样例问题库。
4. 样例问题库只能产生待调查项，不得直接产生已确认规则。

### 质量门禁

新增或加强以下检查：

- 跨字段重复文本
- 跨章节重复文本
- 固定或抽象模板标题
- 审核/编辑话术进入正文
- 样例专属名称、数字或机制污染当前任务
- 复杂机制缺少执行闭环
- 已识别核心对象缺少属性正文
- 图解与当前规则版本不一致
- 表现说明在草图与正文重复
- 概述承诺没有详细落点

门禁输出改善路径，不仅返回通过或失败。

### 当前任务迁移

1. 备份当前任务数据。
2. 清理历史模板字段和重复载体。
3. 按当前素材重新判定适用机制。
4. 将已确认事实写入正文，将不确定逻辑转成决策卡。
5. 重建目录、正文、属性、表格、图解和局部截图位置。
6. 重新生成网站完整预览。

迁移脚本只能消费通用归一化接口；禁止为“一路狂飙”绕过全局门禁或增加仅对该任务生效的渲染分支。

## 测试策略

实现采用测试先行：

1. 先增加失败测试，证明当前版本确实存在重复职责、样例污染和模板标题。
2. 最小修改使单项测试通过。
3. 增加七类机制的内容深度与自然语言测试。
4. 增加至少三种非当前项目的盲测：稀疏移动机制、复杂随机机制、背包或放置机制，证明目录和内容不会复制当前项目或 GVE16 外形。
5. 运行后端、前端和 P1—P7 既有回归测试。
6. 通过浏览器逐章截图，证明目录、正文、图解、截图和参数位置正确。

## 分阶段验收

### 验收点一：生成器根治

- 同一规则只由一个正文载体渲染。
- 样例问题库不会直接生成当前项目事实。
- 标题随机制变化，不出现统一抽象模板。
- 审核话术和重复段落被自动阻断。
- 失败门禁提供具体改善路径。
- 非当前项目盲测会产生各自的机制目录，且不会出现“一路狂飙”或 GVE16 专属对象、数值和标题。

### 验收点二：当前案例重构

- 当前七类机制按适用业务对象组织。
- 表现说明不再挤占玩法正文。
- 随机、战斗、波次和结算规则达到证据允许的闭环深度。
- 未确认逻辑均可在决策卡中处理。
- 逐章与 GVE16 对比适用颗粒度和语言组织。
- 网站预览无重复标题、错误图解、断裂排布或文字代图。

每个验收点都先提交验收用例与操作方法，经用户确认后自检，并为每条浏览器用例提供对应截图路径。

## 通用性完成标准

- 全局规则位于生成模型、质量门禁、知识库和项目 Skill 中，不只存在于当前任务迁移脚本。
- 新 API key、新任务或新上传素材使用同一套规则，不依赖当前会话记忆。
- 新玩法先识别适用领域，再选择正文、图解、截图、表格或决策卡载体。
- 未识别的领域不会生成占位章节；已识别的复杂领域不能因篇幅限制被压缩为概述。
- 当前任务通过只证明首个迁移样本完成；通用能力还必须通过跨玩法盲测。

## 失败与恢复

- 迁移前保存当前任务快照。
- 门禁失败时保留原始模型，不覆盖当前可用预览。
- 当前任务迁移和生成器代码分开提交，便于独立回退。
- 未通过用户验收前不覆盖飞书正式文档。
