# 阶段 4 验收用例：当前任务安全迁移与衍生物重建

状态：等待用户确认用例。确认前不执行正式任务迁移和浏览器自检。

## S4-TC01 干跑不改正式任务

- 目标：迁移前先看清删除、保留和重建范围。
- 前置条件：记录正式任务 ID、文件哈希、玩法 revision、18 个章节及截图数量。
- 操作：对正式任务执行 `dry-run`，读取迁移报告，再次计算任务文件哈希。
- 预期：任务 ID、哈希、revision、章节和截图均不变；报告列出 3 个无来源推断参数、50 个历史快照及 P6/P5 重建数量。
- 截图：干跑报告完整页；执行前后身份与哈希对照页。
- 清理：干跑只产生独立报告，不修改任务。

## S4-TC02 备份可读且能够恢复

- 目标：任何迁移异常都有明确恢复点。
- 前置条件：TC01 通过，正式任务仍为执行前状态。
- 操作：执行迁移；读取时间戳备份；比较备份任务 ID、执行前哈希和关键数据数量。
- 预期：备份 JSON 可解析，任务 ID 一致，备份哈希等于执行前哈希；报告显示备份绝对路径。
- 截图：备份路径、任务 ID、哈希与可读性检查结果。
- 清理：保留本阶段备份直至用户验收；若后续任一用例失败，立即用该备份恢复。

## S4-TC03 策划人工内容不被覆盖

- 目标：清理模板时保留人工确认结果。
- 前置条件：记录迁移前的策划手写玩法概述、目录摘要、18 章确认状态及已确认参数值。
- 操作：执行迁移后逐项计算并比较人工内容快照。
- 预期：策划概述、人工摘要、18 章确认状态和已确认参数值完全一致；迁移报告为“人工内容已保留”。
- 截图：迁移前后人工内容摘要及差异为零的对照页。
- 清理：发现任何差异立即恢复备份，不进入后续用例。

## S4-TC04 历史模板污染清零

- 目标：旧模板既不能留在当前模型，也不能通过撤销历史重新出现。
- 前置条件：迁移前确认存在 3 个无来源推断参数和 50 个旧历史快照。
- 操作：迁移后扫描活动章节、目录、表格、图解、完整预览及玩法编辑历史。
- 预期：无来源推断参数为 0，推断公式为 0，旧历史快照为 0；不得出现“参与某机制计算的数值”、自动编造生命/伤害/抽取/刷新公式等旧模板。
- 截图：迁移前后污染计数和迁移后关键字扫描结果。
- 清理：扫描失败时恢复备份，补清理规则后重跑。

## S4-TC05 P6 表格按当前真实字段重建

- 目标：P6 不再读取历史通用参数表。
- 前置条件：当前 18 章已确认，迁移前仅有一张有效已审核表格。
- 操作：刷新原任务并打开 P6，检查目录、表头、字段、来源、修改值和审核状态。
- 预期：仅显示当前章节中有明确来源和具体值的表格；已确认的人工修改值保留；无参数章节不生成空表；不存在旧生命、伤害、刷新或抽取通用表。
- 截图：P6 完整页面及有效表格详情。
- 清理：不在页面写入额外测试值。

## S4-TC06 图解决策与 P7 当前 revision 一致

- 目标：尊重策划已删除图解的决定，并让 P7 使用迁移后的当前版本。
- 前置条件：迁移前 17 张历史图解均为已删除状态。
- 操作：打开 P5，确认没有旧图解重新出现；打开 P7，读取 gameplay revision、预览 revision、阻断项和正文内容。
- 预期：已删除图解不会复活；P7 的 gameplay revision 等于迁移后的模型 revision；若仍有真实审核阻断，页面必须明确显示且不能冒充可导出。
- 截图：P5 无有效图解状态；P7 完整预览和版本/阻断信息。
- 清理：不得为获得“通过”而伪造图解或强改审核状态。

- 前置条件：TC02–TC06 均通过。

- 预期：仍为任务 `8312a91c89e144e6a59f81b982f14c06`；截图、18 章目录和确认内容未丢失；页面无跳转错误、空白或刷新复位；正式任务 JSON 可解析。
- 截图：原链接身份页、P1 目录、P4 代表章节、P6、P7 完整页面。
