# 飞书样例技巧到项目的蒸馏追踪

机器可校验矩阵位于 `data/calibration/gve16/skill-traceability.json`。当前包含 18 项已重新绑定真实块 ID 的技巧，覆盖率门槛为四项 100%：来源到 Skill、Skill 到项目、项目到测试、测试到 P7/飞书交付。

## 追踪链

每项技巧必须同时存在：

1. 当前 revision 的样例块 ID；
2. 作者的内容选择逻辑；
3. 作者的语言与篇章逻辑；
4. Skill 中的可迁移规则；
5. 项目生成、审计、P7 或发布代码位置；
6. 能在规则退化时失败的测试；
7. 对最终交付产生的可观察效果。

任一环节缺失均视为未蒸馏，不得用“研究完成”代替项目落地。

## 双向孤立检查

- 从每个样例技巧均能找到 Skill、代码、测试和交付效果。
- 从新增门禁均能返回当前两份样例的块级依据或用户明确需求。
- 已撤销的矿坑、组队、迷雾和事件池归因不在矩阵中。
- 样例专属对象、数值和目录不作为项目硬编码规则。

## 等价颗粒度与语言报告

`backend/sample_alignment.py` 对项目每章输出九个证据条件维度，结论仅为 `satisfied`、`missing`、`not_applicable`。同一报告附带语言对照：按制作价值选择内容、主语是否明确、条件—动作—结果—边界是否清楚，以及正文与表格是否重复。复杂章节缺失适用项会阻断；简单章节没有相应证据时保持不适用，不为追求样例篇幅扩写。
