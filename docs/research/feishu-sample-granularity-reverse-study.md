> **来源纠错（2026-08-11）：** 本文件此前把《迷宫开发物语功能文档-1219 副本》概括为“GVE5 矿坑执行文档”，并归入组队、地图生成、迷雾、事件池等内容。重新读取用户提供的 Wiki 链接后确认：它当前仍指向 Docx `S81odB8K2oSqkxx46WAciPd6ntg` revision 61，但正文检索不到上述章节，实际主要内容是魔物、背包、勇者、波次、关卡成长等。第三节及所有依赖“GVE5 矿坑”归因的结论已失去来源资格，在新的逐句来源矩阵完成前不得用于生成或门禁。

研究对象：GVE16 执行文档与《迷宫开发物语功能文档-1219 副本》。UE 流转图仅用于核对相邻视觉证据，不作为固定正文模板。

## 一、结论

样例的高颗粒度不是章节多，而是每条内容都能回答“依据是什么、规则怎样执行、需要配置什么、异常时怎么办”。目录由素材真实存在的玩法系统生成，最深层只在独立机制、算法步骤或状态分支确有必要时出现。

玩法概述必须先让主策一眼看懂：玩家目标、基础操作、核心循环、成长或资源驱动、胜败条件。对象说明（例如载具属性）只能作为系统细节，不能冒充玩法概述。

## 二、GVE16 的证据如何变成正文

| 原始证据 | 能反推出的策划内容 | 应用的表达形式 |
|---|---|---|

| 武器与词条参考资料 | 武器类型、基础伤害比例、元素伤害、目标数、衰减、索敌与伤害范围、解锁和词条前置 | 内容清单、参数表、解锁与随机池规则 |
| 载具配置说明 | 等级、升级消耗、攻击/生命/减伤字段、不可逆与活动结束重置 | 等级规则、配置字段表、生命周期 |
| 波次配置说明 | 路程、刷怪点、停车、移速倍率、怪物倍率、经验和波次奖励 | 波次参数表、推进规则、边界 |
| 词条三选一/老虎机规则 | 不放回、按栏位顺序、空结果权重、类型权重、词条池、暂存、确认、重抽消耗与重置 | 分步算法、权重公式、分支矩阵、参数表 |
| 伤害统计与结算资料 | 总伤/秒伤公式、归属口径、排序、实时刷新、失败与胜利奖励 | 公式块、统计规则、结算分支 |

可见一个“武器选择界面”不能只生成“随机武器抽取”。当证据充分时，应继续拆出候选池、武器类型、词条前置、栏位抽取顺序、权重、重复限制、重抽成本、暂存结果和结束重置。

算法章节必须保留逐步判断与分支。例如迷宫生成不能缩成“随机生成迷宫”，而要写清待定格列表、对面格判断、陆地/墙壁变更、循环终止与出口距离约束。

## 四、通用反向证据链

1. 截图和视频证明可见对象、状态、顺序、反馈和显示数值。
2. 参考文档证明隐藏规则、前置、异常、重置、持久化与配置字段。
3. 配置表证明内容清单、字段类型、单位、范围、默认值和投放来源。
4. 会议与技术说明证明端侧职责、算法选择、同步与退出重进。
5. 策划确认补齐素材无法展示但必须决策的规则。

任何结论必须回指至少一种证据。画面只有结果时，只能确认结果；不得反推未展示的概率、公式、配置字段或存储职责。

## 五、生成与主策检查

- 先生成玩家视角概述，再建立自适应目录；禁止用对象介绍代替玩法概括。
- 发现多个可区分武器、敌人、奖励、事件或状态时，形成逐项内容清单，不得写成“存在多种”。
- 参数机制输出正式策划字段表；计算机制输出变量、顺序、修正、取整、边界和有依据的算例。
- 随机机制必须覆盖候选池、资格、权重、顺序、放回方式、重复、空结果、上限、刷新与重置。
- 生命周期必须区分正常退出、重新进入、强退重登、局内结束、关卡结算和活动结束。
- 图片只服务于布局、组件分组、状态对比或算法步骤。纯文字与单独公式不生成图解。
- 输出前自动拦截：看图写话、交互术语冒充玩法、固定模板、证据错配、重复章节、缺参数/公式/边界、英文内部字段、乱码、无意义图解。

## 六、逐级目录与正文深度实证（2026-08-10 复核）

### GVE16

- 目录并未止于“载具、武器、怪物、战斗、关卡”。载具继续拆到基础属性、等级、武器栏、特权；武器继续拆到类型、基础属性、解锁、养成、词条基础属性、词条解锁、词条效果；怪物拆到刷新、移动、攻击、受击及死亡。
- 战斗继续拆到战斗属性、伤害计算、战力计算、演出、跳字；关卡继续拆到流程、地图、波次、载具移动、战斗等级、词条获取条件、三选一、老虎机、BUFF、伤害统计、时限、倍速、失败、胜利、解锁、挑战、首通奖励和扫荡。
- 正文包含可实现表达，例如“玩家战力 = Σ（属性值 × 对应战力系数）”，并把系数落到 `GveMagicBookAttr.powerAdd`；演出规则还给出静止→加速→匀速的顺序、标准移速引用、胜利后继续前进的时长和结算出现顺序。

### GVE5

- 目录按活动调度、组队、地图、探索、事件动态组织，完全不同于 GVE16。活动拆阶段和结束数据处理；组队拆创建、加入、退出、管理、解散和界面信息；地图拆层级、地块、生成、人偶、迷雾和层级切换；探索拆状态、消耗、条件、结果和表现流程；事件拆固定事件、随机事件和具体事件类型。
- 地图生成不是“随机生成”一句话：明确普通层与无限层、模板循环、取模公式、生成批次、全服一致性、共享配置、长宽奇偶修正、地块编码、出生点存储职责，并给出代入算例。

## 七、当前工具输出的对比缺口与修复合同

| 内容角色 | 样例标准 | 当前任务必须做到 |
|---|---|---|
| 玩法概述 | 玩家目标、操作、循环、成长/资源、胜败 | 禁止用载具或页面说明代替；五项缺一即退回 |
| 内容清单 | 可区分对象逐项列出 | 已识别的武器、强化、敌人、状态不得概括为“多种” |
| 配置字段 | 表名、字段、含义、类型、单位、范围、来源 | 有参考文档/表格才输出精确名称；纯截图不得臆造 |
| 执行顺序 | 算法步骤、触发、分支、终止 | 随机池、波次、状态切换和结算按执行次序表达 |
| 公式与算例 | 变量、顺序、修正、取整、边界、代入值 | 有依据才生成；缺依据时列出需要策划决定的具体项 |
| 异常边界 | 重复、空结果、无效目标、上限、失败 | 正常正文不能只覆盖成功路径 |
| 生命周期 | 退出、重进、强退、局内/关卡/活动结束 | 各状态分别记录保留、清除和重置 |
| 图文证据 | 图只证明对应布局、状态或步骤 | 不复用错图，不用纯文字伪图解，局部图解释属性和规则 |

P7 的最终正文必须同时包含交互与页面流程、玩法概述、动态玩法正文、必要图解和业务配表。标题层级应由实际系统结构生成；不得把工作台审核字段原样当成最终目录。
