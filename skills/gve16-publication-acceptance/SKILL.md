# GVE16 Publication Acceptance

Use the first-party GVE16 document and the project’s authoritative gap audit as responsibility references, never as content authority.

## Body acceptance

1. Extract the real GVE16 heading tree before editing the project body.
2. Compare the final artifact title by title, paragraph by paragraph, table row by table row, and figure placement by figure placement. Print the actual final text in the crosswalk; IDs or keyword hits are not evidence.
3. Preserve project-specific reader aids such as an overview or linear run flow, but keep detailed rules under their Primary Owner.
4. Reject compound headings when they hide independent owners, mechanisms, states, or carriers. Do not mechanically ban conjunctions: a natural term may contain one, but each heading still needs one editorial responsibility.
5. A related sentence does not satisfy an atomic question unless it states the missing condition, selection rule, formula, branch, result, attribution, or reset.
6. Place each P5 diagram and P6 table immediately after the rules that consume it. An audit tab or detached appendix does not replace an inline figure.

## Carrier consistency

- Generate web and Feishu from one canonical body and the same BOARD/P5/P6 anchors.
- Feishu automatic numbering must wrap the real body headings. Never prepend a separate numbered directory or hand-write heading numbers.
- Keep UE flow, planning sketch, and competitor reference as distinct boards when the project contract calls for three boards.
- UE flow pages show numbered component markers on the actual component regions and adjacent explanations of purpose, input, system feedback, result, and return behavior.
- Planning sketch communicates page/state composition and presentation logic; it is not a flowchart duplicate. Competitor reference contains reference material, not current-project rules.

## Visual gate

Inspect both a rendered preview and raw structure. Reject delivery if text, images, numbers, arrows, or labels overlap; if a marker and its explanation point to different components; if connectors cross readable text; if a flow collapses into a vertical explanation list; or if the default board overview is unreadable.

For web, exercise every visible navigation control, direct-link state, reload state, and next-step transition. Capture failures at the destination state, not just before a click.

## Publication protocol

1. Finish and commit the canonical local artifact.
2. Read the live remote revision and body before overwrite.
3. Abort on revision conflict; never bypass the conflict guard.
4. Overwrite the same authorized document, then rebuild or update board structures and media through stable checkpoints.
5. Reverse-verify from the live Feishu document: actual text and tables, native numbering, board presence, preview readability, raw image tokens and dimensions, and absence of stale headings.
6. Do not claim completion from tests, closure-state counts, node counts, or local artifacts alone.

External writes, authentication, and publication still require the authority granted for the current task.
